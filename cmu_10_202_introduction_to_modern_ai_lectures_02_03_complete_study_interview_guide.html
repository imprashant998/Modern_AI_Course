2.1 The Supervised Machine Learning Paradigm vs. Usual Programming

Page 1

Virtually every modern AI system—including large language models (LLMs) like ChatGPT, Gemini, and Claude—is built algorithmically upon the supervised machine learning paradigm (often termed self-supervised learning when input-output pairs are extracted automatically from raw text, though the underlying training algorithm is identical). To understand why supervised ML is revolutionary, contrast it with how we write traditional software:

Architecture Diagram: Usual Programming Approach vs. Machine Learning Approach
When Usual Programming Excels

When we have an exact mathematical specification of preconditions and postconditions—such as sorting a list of numbers—we can think through the step-by-step logic and formalize it directly in Python code.

Why We Need the ML Approach

For tasks like classifying raw pixel arrays into "cat" vs. "dog" or answering open-ended questions in a chatbot, writing explicit rules is intractable. However, collecting examples of inputs and desired outputs (saying what we want rather than how to compute it) is straightforward. Notice the distinction: the ML Algorithm is the meta-program we write; the "Program" (Model) it outputs is a mathematical function parameterized by weights.

2.2 Core Terminology & Notation

Page 1
"Input"
Input Example

The input that we will provide to the ML-produced program (e.g., an image pixel grid or the starting words/prefix of a sentence).

"Desired output" (Target)
Target Label / Output

The output we want our ML program to produce for some corresponding input (also called targets or ground truth in literature).

"Training set"
Dataset of Pairs

A collection of inputs and their corresponding desired outputs, fed into the ML algorithm to build/train the ML program.

2.4 The Three Ingredients of Every Machine Learning Algorithm

Pages 2–3

Every machine learning algorithm—whether simple linear regression, gradient-boosted decision trees, or a frontier Transformer LLM—is completely defined by three specific choices:

Ingredient 1: MODEL (and MODEL CLASS / Architecture)

h : Inputs → Predicted outputs

The Model (the ML program produced by training) is a function h (historically standing for hypothesis) that maps "inputs" to "predicted outputs". Crucially, even when the desired output in the training set is a discrete label like "cat", we typically design the model to output a list of probabilities (a soft prediction):

🐱
Cat Image
(Input)
→ [ Model h ] →
[ 0.1,   0.9 ]
P(dog) = 0.1 P(cat) = 0.9
(Predicted Output: List of Probabilities)
Model Class (Architecture)

Searching over the space of all possible mathematical functions is intractable and would severely overfit. The Model Class (called the Architecture in modern deep learning) is the allowed set / family of models we consider to solve a particular problem (e.g., the family of all Linear Models, or Neural Networks / Transformers of a specific layer depth and hidden dimension).

Ingredient 2: LOSS FUNCTION

L : Predicted outputs × Desired outputs → ℝ₊

A function that measures the discrepancy/difference between the model's predicted output h(input) and the ground-truth desired output. Formally, it maps a pair of (predicted output, desired output) to a non-negative real scalar (ℝ₊ = [0, ∞)):

Loss is "LARGE" if the prediction is bad (far from the desired output).
Loss is "SMALL / ZERO" if the prediction is good (matches the desired output closely).

Lecture Note on 0-1 Loss vs. Cross-Entropy: One could define a simple loss that equals 0 if the highest-probability class matches the target and 1 otherwise (0-1 loss), but in practice we use probability-based losses like Cross-Entropy Loss because they are smooth (differentiable for optimization) and directly model probability distributions required for tasks like language modeling.

Ingredient 3: OPTIMIZATION PROCEDURE (Training)

Minimize Empirical Risk over Training Set

The goal of the optimization procedure is to find THE MODEL (or a model) within the allowed model class that achieves low loss on the training set—specifically, minimizing the sum of losses over all input / desired-output pairs in the training set:

minimize h ∈ Model Class   ∑(input, desired o/p) ∈ Training Set L( h(input), desired output )
Crucial Modern AI Insight (Page 3 Highlight)

In modern AI, the loss function and optimization procedure are almost always fixed across tasks: virtually every modern system uses Cross-Entropy Loss and some flavor of Gradient Descent (such as Stochastic Gradient Descent or Adam). It is the Model Architecture (Model Class)—and the training data—that varies!

2.5 Generalization, The Lookup-Table Trap & Downstream Tasks

Page 3
1. Why Training Loss Alone Fails

Finding a model with zero loss on the training set is trivial: a simple Python dictionary / database lookup table (`dict[input] = desired_output`) memorizes the training set with 0 loss, yet fails completely on any new image or sentence!

2. Classical Generalization (Test Set)

The true beauty of ML is building a model that performs well on unseen examples from the same distribution. We measure this using a held-out Test Set of (input, desired output) pairs never shown during optimization.

3. Modern General AI: Downstream Tasks

Nobody picks an LLM chatbot by checking its held-out cross-entropy loss on next-word prediction! For General AI, we test models on downstream tasks—e.g., solving math problems or writing code via multi-token sampling. Remarkably, optimizing next-token training loss causes strong downstream capabilities to emerge!

3.1 Lecture Recap & Vectors: 1D Arrays of Numbers

Page 4
Recap: The 3 Ingredients of ML & Why Linear Algebra Matters
1. Model: Maps inputs to predicted outputs. Linear algebra is the formal language used to specify models!
2. Loss fn: Measures quality of predictions.
3. Optimization: Finds a model with low loss.

From a practical computer science perspective, a vector is a one-dimensional (1D) array of numbers. We write:

x ∈ ℝn   ⇒   x = 437 ∈ ℝ3
  • Terminology Nuance ("1D Array" vs. "n-Dimensional"): Calling a vector "1D" means we index along a single axis (unlike a 2D matrix with rows and columns), whereas saying x ∈ ℝn is "n-dimensional" refers to its length n.
  • Element Notation: xi refers to the ith element of x. In the example above, x2 = 3.
  • Critical Indexing Convention: We use one-indexing in mathematical notation (x1, x2, …, xn) and zero-indexing in Python/PyTorch (x[0], x[1], ..., x[n-1]).
Visualizing Math 1-Indexing vs. Python 0-Indexing
Operation 1: Vector-Vector Addition

For x, y ∈ ℝn (must have the exact same length n), addition is element-wise:

x + y = [ x₁ + y₁,   x₂ + y₂,   …,   xₙ + yₙ ]T ∈ ℝn
Operation 2: Scalar Multiplication

For x ∈ ℝn and scalar c ∈ ℝ, multiply every entry by c:

c x = [ c·x₁,   c·x₂,   …,   c·xₙ ]T ∈ ℝn

3.2 Vector-Vector Multiplication (Inner / Dot Product) & PyTorch

Page 5

While you can multiply two vectors element-wise (Hadamard product x * y), the most fundamental vector-vector multiplication in linear algebra and machine learning is the inner product (or dot product). For x, y ∈ ℝn, it multiplies corresponding entries and sums them into a single real-valued scalar:

⟨x, y⟩ ≡ xTy = x₁y₁ + x₂y₂ + … + xₙyₙ = ∑i=1..n xi yi ∈ ℝ   (Real-valued scalar)
# PyTorch Implementations: Vectors & Inner Product (Page 5) 
import torch

# Create a 1D tensor (vector in R^3)
x = torch.tensor([1, 2, 3])
print(x)          # tensor([1, 2, 3])

# Indexing (0-indexed in Python! x[0] is 1st element, x[1] is 2nd element)
print(x[1])       # tensor(2)

# Vector addition & scalar multiplication
y = torch.tensor([4, 5, 6])
print(x + y)      # tensor([5, 7, 9])
print(2 * x)      # tensor([2, 4, 6])

# Inner product (dot product) using the overloaded @ operator:
# 1*4 + 2*5 + 3*6 = 4 + 10 + 18 = 32
print(x @ y)      # tensor(32)

3.3 Matrices, Transpose & Column/Row Representations

Pages 5–6

A matrix is a 2D array of numbers denoted A ∈ ℝm × n, where the first dimension m is the number of rows and the second dimension n is the number of columns.

A ∈ ℝ2 × 3 = 732 248

Indexing (Aij): Refers to the entry in the ith row and jth column. In the matrix above, A12 = 3 (1st row, 2nd column in 1-indexed math; in PyTorch 0-indexed: A[0, 1] == 3).

1) Matrix Addition (A, B ∈ ℝm × n)
C = A + B ∈ ℝm × n where Cij = Aij + Bij.
2) Matrix-Scalar Multiplication (A ∈ ℝm × n, c ∈ ℝ)
B = cA ∈ ℝm × n where Bij = c · Aij.
3) Matrix Transpose (A ∈ ℝm × n ⇒ B = AT ∈ ℝn × m)
Swaps rows and columns: Bij = Aji (the ith row of A becomes the ith column of AT).
Symbolic Transpose (Page 6 Notes)
A₁₁A₁₂A₁₃ A₂₁A₂₂A₂₃ A₃₁A₃₂A₃₃ T  =  A₁₁A₂₁A₃₁ A₁₂A₂₂A₃₂ A₁₃A₂₃A₃₃
Concrete 2×3 → 3×2 Transpose (`A.T` in PyTorch)
732 248 T  =  72 34 28 ∈ ℝ3 × 2
Column vs. Row Vector Rule

By mathematical convention, any vector x ∈ ℝn is always considered a column vector (an n × 1 matrix). To denote a row vector (1 × n matrix), we explicitly write the transpose xT.

PyTorch Caveat: In PyTorch, 1D tensors torch.tensor([7,3,2]) have shape (3,) and do not distinguish row vs. column; calling x.T on a 1D tensor is a no-op with a warning!

Matrix in Terms of Its Columns
A = [   a₁  |  a₂  |  …  |  aₙ   ] ∈ ℝm × n

Here A has n columns, and each column vector ai ∈ ℝm is an m-dimensional column vector. In PyTorch: A[:, i].

Matrix in Terms of Its Rows
A = [ — a₁T — ;  — a₂T — ;  … ;  — aₘT — ] ∈ ℝm × n

Here A has m rows, where each aiT ∈ ℝ1 × n is a row vector (ai ∈ ℝn). In PyTorch: A[i, :]. (Note: row aiT is NOT the transpose of column ai!)

3.4 Matrix-Vector Multiplication (Ax): Two Dual Interpretations

Page 7

For A ∈ ℝm × n and x ∈ ℝn (notice the inner dimensions n must match!), the product Ax ∈ ℝm is an m-dimensional column vector defined entry-by-entry as (Ax)i = ∑j=1..n Aij xj. Understanding both geometric/structural interpretations is essential:

Interpretation 1: Collection of Inner Products (Row-Wise View)

Decompose A into its m rows. The ith entry of Ax is simply the dot/inner product of the ith row of A with the vector x:

Ax = — a₁T — — a₂T — ⋮ — aₘT — |x| = a₁T x a₂T x ⋮ aₘT x ∈ ℝm
Interpretation 2: Linear Combination of Columns of A (Column-Wise View)

Decompose A into its n columns. Then Ax is a weighted sum (linear combination) of the columns of A, where the coefficients are given by the entries of x:

Ax = ||| a₁a₂aₙ ||| x₁x₂xₙ = a₁x₁ + a₂x₂ + … + aₙxₙ = ∑i=1..n ai xi

3.5 Vector-Matrix Multiplication (xTA): Two Dual Interpretations

Page 8

When we multiply a row vector xT ∈ ℝ1 × m (where x ∈ ℝm) on the left of a matrix A ∈ ℝm × n, the result is a row vector xTA ∈ ℝ1 × n defined entry-by-entry as (xTA)i = ∑j=1..m xj Aji:

Interpretation 1: Collection of Inner Products with Columns

Write A in terms of its columns a₁, a₂, …, aₙ. Each entry of the resulting row vector is the inner product of x with the ith column of A:

[ — xT — ] ||| a₁a₂aₙ ||| = [   xTa₁    xTa₂    …    xTaₙ   ] ∈ ℝ1 × n
Interpretation 2: Linear Combination of the Rows of A

Write A in terms of its rows a₁T, a₂T, …, aₘT. Then xTA is a linear combination of the rows of A weighted by the entries of x:

[ x₁   x₂   …   xₘ ] — a₁T — — a₂T — — aₘT — = x₁[a₁T] + x₂[a₂T] + … + xₘ[aₘT] = ∑i=1..m xi aiT

3.6 Numerical Walkthrough & PyTorch Coding: A @ x and z @ A

Page 9
Walkthrough 1: Matrix-Vector Product (A @ x)
732 248 123 = 7(1) + 3(2) + 2(3) 2(1) + 4(2) + 8(3) = 7 + 6 + 6 2 + 8 + 24 = 19 34
  • • Row 0 Inner Product: A[0, :] @ x == 19
  • • Row 1 Inner Product: A[1, :] @ x == 34
  • • Column Linear Comb: A[:,0]*x[0] + A[:,1]*x[1] + A[:,2]*x[2] → [19, 34]
Walkthrough 2: Vector-Matrix Product (z @ A)
[ 1   2 ] 732 248 = [ (1·7 + 2·2),   (1·3 + 2·4),   (1·2 + 2·8) ] = [ 11, 11, 18 ]
  • • Col Inner Products: [z @ A[:,0], z @ A[:,1], z @ A[:,2]] → [11, 11, 18]
  • • Weighted Combination of Rows: 1 * [7, 3, 2] + 2 * [2, 4, 8] = [11, 11, 18]
# PyTorch Code: Matrix-Vector & Vector-Matrix Products (Page 9) 
import torch

A = torch.tensor([[7, 3, 2],
                  [2, 4, 8]])   # shape: (2, 3)
x = torch.tensor([1, 2, 3])     # shape: (3,)

# 1. Matrix-Vector Product (A @ x) -> shape (2,)
print(A @ x)                                        # tensor([19, 34])
print(A[0, :] @ x, A[1, :] @ x)                     # tensor(19) tensor(34) (Interp 1: row inner products)
print(A[:, 0]*x[0] + A[:, 1]*x[1] + A[:, 2]*x[2])   # tensor([19, 34])      (Interp 2: col linear combination)

# 2. Vector-Matrix Product (z @ A) -> shape (3,)
z = torch.tensor([1, 2])        # shape: (2,)
print(z @ A)                                        # tensor([11, 11, 18])
print([z @ A[:, 0], z @ A[:, 1], z @ A[:, 2]])      # [tensor(11), tensor(11), tensor(18)] (Interp 1: col inner products)
print(1 * A[0, :] + 2 * A[1, :])                    # tensor([11, 11, 18])  (Interp 2: weighted combination of rows)

3.7 Matrix-Matrix Multiplication (AB): Three Core Interpretations

Page 10
Formal Definition & Shape Compatibility Rule (m × n) · (n × p) ⇒ (m × p)

For A ∈ ℝm × n and B ∈ ℝn × p, the number of columns of A (n) must equal the number of rows of B (n). The shared inner dimension n drops out, producing AB ∈ ℝm × p where:

(AB)ij = ∑k=1..n Aik Bkj

Note on Handwritten Notes & Lecture Errata: On Page 10 of the handwritten notes, the summation term is written AikBij (a small pen slip for AikBkj), and in the Lecture 3 video at 1:15:50 Prof. Kolter initially wrote column bn before correcting it to bp at 1:19:10.

Interpretation #1: Collection of Inner Products

Write A by its m rows (aiT ∈ ℝ1 × n) and B by its p columns (bj ∈ ℝn). Every (i, j) entry is the inner product aiT bj:

— a₁T — — a₂T — — aₘT — ||| b₁b₂bₚ |||
=
a₁Tb₁a₁Tb₂a₁Tbₚ a₂Tb₁a₂Tb₂a₂Tbₚ aₘTb₁aₘTb₂aₘTbₚ
Interpretation #2: Collection of Matrix-Vector Products

Keep A intact as a matrix and decompose B by its columns. Then A acts on each column bj independently side-by-side:

[   A   ] ||| b₁b₂bₚ |||
=
||| Ab₁Ab₂Abₚ |||

Each column of AB is a linear combination of the columns of A!

Interpretation #3: Collection of Vector-Matrix Products

Decompose A by its rows and keep B intact as a matrix. Each row of AB is the vector-matrix product aiT B:

— a₁T — — a₂T — — aₘT — [   B   ]
=
— a₁TB — — a₂TB — — aₘTB —

Each row of AB is a linear combination of the rows of B!

3.9 Properties of Matrix Multiplication & PyTorch Tensors

Pages 11–12
Status Property Mathematical Identity Practical / Interview Implication
✓ Holds Distributive A(B + C) = AB + AC Allows factoring linear expressions and combining parallel linear projections.
✓ Holds Associative (AB)C = A(BC) Identical result, vastly different speed! If A, B ∈ ℝn × n and c ∈ ℝn × 1, computing (AB)c takes O(n³) FLOPs, whereas A(Bc) takes only O(n²) FLOPs!
× Fails Not Commutative AB ≠ BA Order strictly matters! For non-square matrices BA may not even have valid dimensions; even for square matrices AB ≠ BA (except special cases like identity/diagonal).
✓ Holds Transpose of Product (AB)T = BTAT The transpose of a product reverses the order of the factors ("shoe-sock rule").
# PyTorch Matrix Multiplication & Tensors (Page 12) 
import torch

# Matrix A: 2x3, Matrix B: 3x3 (from Page 12 notes)
A = torch.tensor([[7, 3, 2],
                  [2, 4, 8]])
B = torch.tensor([[5, 6, 7],
                  [4, 2, 3],
                  [3, 2, 5]])

print(A.shape)    # torch.Size([2, 3]) -> property of Tensor class
print(B.shape)    # torch.Size([3, 3])
print(A @ B)      # tensor([[53, 52, 68],
                  #         [50, 36, 66]])  -> shape (2, 3)

# 3D "Tensors": Think of higher-order tensors as stacks of matrices!
T = torch.tensor([
    [[7, 3, 2], [2, 4, 8]],   # Slice 0: T[0, :, :] (2x3 matrix)
    [[3, 2, 3], [1, 8, 9]]    # Slice 1: T[1, :, :] (2x3 matrix)
])
print(T.shape)    # torch.Size([2, 2, 3]) -> (stack/batch, rows, cols)
Think of Tensors as "Stacks of Matrices" (Page 12)

While pure mathematics defines tensors via multi-linear algebraic transformations, in PyTorch and deep learning a "Tensor" simply means a multi-dimensional array:

  • • 1D Tensor: Vector (n,)
  • • 2D Tensor: Matrix (m, n)
  • • 3D Tensor: Stack of matrices (batch_size, seq_len, hidden_dim)
Why GPUs Rule Modern AI (Lecture 3 Closing Note): Roughly 99% of all computation in modern Large Language Models boils down to matrix-matrix multiplications (A @ B). Graphics Processing Units (GPUs) became the backbone of AI specifically because their massive parallel tensor cores are purpose-built to execute dense matrix multiplications at extreme throughput.
